# معرفة مَدخَل الأساسية

## هوية المشروع
مَدخَل — المدخل إلى سوق العمل الإلكتروني / سوق العمل لحظة بلحظة.

## الهدف
ربط الباحث عن عمل بالفرص المناسبة، مع ملف مهني وتقييم ومطابقة وتنبيهات ومتابعة، وربط صاحب الفرصة بالباحثين المناسبين.

## مسار الباحث
ملف مهني → المهارات/التفضيلات → التقييم → المطابقة → عرض الفرصة → التقديم → متابعة الطلب.

## مسار صاحب الفرصة
صاحب الفرصة → إنشاء فرصة → حفظها → ظهورها في المطابقة المناسبة → استقبال الطلبات ومتابعتها.

## قواعد UX المعتمدة
- زر «أبحث عن عمل» يبدأ رحلة الملف/المهارات/ما يبحث عنه المستخدم، وليس تحويلًا مباشرًا إلى قائمة عامة.
- البحث الأساسي والمشاهدة الأساسية مجانيان.
- الاشتراك مخصص للمتابعة المستمرة والتنبيهات والمطابقة المستمرة وفق السعر والآلية المعتمدة في النسخة الحالية.
- لا تُفرض آلية دفع غير موثقة أو غير متاحة للمستخدم.
- يجب أن تبقى الواجهة بسيطة ومناسبة للهاتف.

## بيانات مَدخَل المهمة في Supabase
من البيانات التي يجب على الوكيل معرفتها عند الفحص:
- public.profiles
- public.worker_profiles
- public.profile_skills
- public.job_preferences
- public.jobs
- public.employer_vacancies
- public.applications
- public.madkhal_applications
- professional_evaluations والجداول المرتبطة بها
- subscriptions والجداول المرتبطة بالمتابعة/الاشتراك
- أي جداول أو وظائف أخرى يثبت الفحص أنها جزء من مسار مَدخَل.

## نطاق محمي
public.jobs ومصادر الوظائف والاستيراد والـCron والبيانات التاريخية العاملة تعتبر أنظمة محمية.

## خارج نطاق الوكيل
جداول المطعم والبوت مثل:
- restaurants
- menu_categories_v2
- menu_products_v2
- product_options
- customers_v2
- orders_v2
- order_items_v2
- delivery_zones
وأي نظام آخر لا يخص مَدخَل.

وجود هذه الأنظمة في نفس مشروع Supabase لا يمنح الوكيل صلاحية تعديلها.

## ملاحظة
قائمة الجداول ليست بديلًا عن فحص schema الفعلي؛ على الوكيل التحقق قبل اتخاذ أي قرار.
