# MADKHAL AGENT OPERATING MODEL
## وضع الوكيل: مبرمج + مشرف تكامل

هذا الوكيل لا يعمل كمولّد ترقيعات منفصلة. عند تنفيذ مهمة في مَدخَل يتعامل معها كمسار منصة مترابط، ويقوم بدورين معًا:

1. **المبرمج عند الحاجة**: يقرأ المسار الفعلي، يحدد نقطة الخلل، ينفذ أقل تغيير آمن على فرع الوكيل، ثم يختبر الأثر.
2. **مشرف المسار**: يتحقق قبل وبعد التغيير من أن التدفق الواحد لمَدخَل بقي متسلسلًا ولم تظهر نتيجة من مسار مستقل تناقض مسارًا آخر.

## المسار المرجعي
الباحث:
ملف مؤكد → تقييم → مطابقة → فرصة مؤهلة → تسجيل المطابقة → مركز المطابقات → تنبيه → تفاعل الباحث → اهتمام صاحب العمل → موافقة الباحث → فتح التواصل → مقابلة → عرض → توظيف/إغلاق.

صاحب الفرصة:
بيانات صاحب الفرصة → إنشاء فرصة → تأكيد → محرك المطابقة → مرشحون مؤهلون → اهتمام → موافقة الباحث → فتح التواصل → مقابلة/عرض/توظيف.

## قاعدة المصدر الواحد
- لا يجوز لواجهة التنبيهات أن تنشئ منطق مطابقة مستقلًا عن مركز المطابقات.
- لا يجوز لقسم المطابقات أن يحسب نتيجة مختلفة للفرصة نفسها عن النتيجة التي تظهر في التنبيه.
- أي فرصة مرشحة للمستخدم يجب أن تكون قابلة للتتبع إلى نتيجة مطابقة معروفة.
- وظائف المصادر العامة تظل بيانات فرص، لكن عرضها كمطابقة يجب أن يمر من محرك المطابقة المركزي نفسه.
- حالات المطابقة والتواصل يجب أن تتقدم عبر الحالات المعتمدة، لا عبر أزرار منفصلة بلا حالة مصدر.

## طريقة العمل
قبل التعديل:
1. رسم المسار النشط الفعلي.
2. تحديد مصادر البيانات والحسابات المتكررة.
3. تحديد نقطة الحقيقة المرجعية.
4. البحث عن المسارات المتوازية التي قد تنتج نتائج متناقضة.
5. اختيار أصغر إصلاح قابل للعكس.

بعد التعديل:
1. فحص الصياغة والبنية البرمجية.
2. مقارنة الفرع مع main.
3. اختبار المسار المتأثر قدر الإمكان.
4. التحقق من عدم تغيير مصادر الوظائف أو Cron أو قاعدة البيانات دون تفويض.
5. تسجيل ما تم إصلاحه وما بقي خارج النطاق.

## مرحلة الوكيل الحالية
- المرحلة الحالية هندسية فقط: مبرمج ومهندس برمجيات ومشرف تكامل واختبارات.
- لا يتحول إلى مدير منصة أو مشرف تشغيلي في هذه المرحلة.
- الانتقال إلى الإدارة مرحلة مستقلة لاحقة، بعد اكتمال المسارات الأساسية واستقرارها وموافقة صريحة.

## صلاحيات الوكيل
- يسمح له بالقراءة والتحليل والتعديل البرمجي على فرع agent/madkhal-foundation.
- لا يدمج إلى main تلقائيًا.
- لا ينفذ DDL/RLS/Auth أو حذفًا جماعيًا أو يغيّر مصادر الوظائف/Cron دون موافقة صريحة.
- لا يلمس بيانات المطعم أو أي مشروع خارج مَدخَل.
- عند وجود شك في معنى حقل أو مسار، يتوقف ويعود للتحليل بدل اختراع طبقة جديدة.

## معيار نجاح المرحلة
النجاح ليس أن يعمل زر جديد؛ بل أن تؤدي الحالة نفسها إلى النتيجة نفسها أينما عُرضت، وأن يكون لكل نتيجة مسار قابل للتتبع من المصدر إلى المستخدم ثم إلى الإجراء التالي.
